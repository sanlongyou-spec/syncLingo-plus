# 编码规范

> 本文档为项目统一遵守的编码标准，适用于所有 Java 后端和 React/TypeScript 前端代码。

---

## 一、后端架构要求

1. 必须使用分层架构：
   `controller → facade → service → integration → mapper`

2. 禁止跨层调用（controller 不能调 mapper）

3. 外部 API 必须放在 integration 层

4. 必须使用 DTO / VO / Entity 分离

---

## 二、后端代码规范

1. 所有接口必须返回统一 Result 结构

2. 必须使用 Lombok（`@Data` `@Slf4j`）

3. 必须包含完整日志（`info` + `error`）

4. 必须包含异常处理（`BizException` + 全局异常）

5. 禁止使用 `System.out.println`

6. 禁止魔法值，必须使用常量

7. 命名必须清晰（禁止 tmp、data 等）

---

## 三、后端日志要求

1. 每个方法必须有日志（开始 + 结束）

2. 外部调用必须记录耗时

3. 日志必须包含关键参数

---

## 四、前端规范（React）

1. 所有请求必须封装在 api 目录

2. 禁止在组件中直接写 axios

3. 页面和组件分离（views / components）

4. 使用 ES6（`const` / `let`），禁止 `var`

---

## 五、输出要求（必须遵守）

1. 必须输出完整代码（不能省略）

2. 必须标注包路径

3. 每个类必须有注释

4. 不允许只给示例或伪代码

5. 所有依赖类必须一并给出

---

## 六、修改代码时

1. 只修改指定部分，禁止改动无关代码

2. 保持原有结构不变

---

## 七、全面测试要求

1. 修改代码后必须进行全面测试，不能只验证接口可访问、返回成功或代码能够编译。

2. 必须验证本次修改的正常流程、失败流程、权限与安全边界、重要边界条件以及相关回归流程。

3. 每个被修改模块必须运行完整测试套件和构建；涉及跨模块契约、共享行为或完整用户流程时，必须执行跨模块验证。

4. 修改前端交互或样式后，必须在浏览器中验证实际操作流程，并检查桌面与移动端布局及加载、空数据、错误、禁用、成功等相关状态。

5. 必须按需检查日志、接口响应、数据库记录、生成文件和运行时状态，以证明业务行为正确。

6. 必需测试失败时不得宣称任务完成。由本次修改引入的失败必须修复；历史失败必须提供证据并说明残余风险。

7. 因环境限制无法执行必需测试时，必须明确说明未测试内容、原因和风险。
